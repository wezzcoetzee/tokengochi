Recommended v1

Scope

  • Show one menu-bar item per active provider: one Claude creature and one Codex creature.
  • Keep separate pet rules, snapshots, freshness, and reset state per provider.
  • Add a Codex local activity producer that records turn token usage from JSONL events or a hook script.
  • Add Codex-specific reset fields: available resets, used resets, next reset time, and source quality.
  • Rename the existing unlockable claude creature skin to codex, then use it as the Codex provider's creature.

Non-goals for v1

  • Do not try to clone Anthropic's OAuth poller without an official OpenAI endpoint for equivalent data.
  • Do not read private auth files directly for billing data.
  • Do not mix Claude and Codex values into one creature or one window.
  • Do not use a provider selector as the primary UX; multiple subscriptions should be visible at once.
  • Do not promise exact Codex plan-limit percentages until the data source is verified.

Data source options

OptionWhat it givesFitRisk
Codex JSONL turn.completed includes usage fields like input, cached input, output, and reasoning output tokens. Best for v1 local Codex activity and token totals. Only covers Codex runs launched in a way Tokengochi can observe; reset counts may not appear here.
Codex hooks Command hooks can run on lifecycle events such as Stop, PostToolUse, and SessionStart. Good for interactive CLI integration if hook payload includes enough usage context or can locate session logs. Needs a spike against real hook payloads, especially reset metadata.
Enterprise analytics Workspace usage can include threads, turns, credits, clients, and token fields. Possible fallback for reset/usage history, not the default pet loop. Admin-gated and usage can lag up to 12 hours.
Live quota API Would be ideal: session %, weekly %, reset count, reset times. Perfect if it exists for the user's auth path. Not confirmed in the current official Codex docs.

Implementation phases

1

Multi-provider snapshot store

Add UsageProvider, source metadata, and per-provider snapshot files. Preserve existing decoding by migrating today's snapshot.json into the Claude slot.

  • provider: claude | codex
  • snapshot-claude.json and snapshot-codex.json
  • windowKind: exact | estimated
2

Producer abstraction

Rename the merge API around observations rather than Claude producers. Keep the current Claude writer and poller behavior intact, but write into the Claude snapshot only.

  • AccountUsageObservation owns session/weekly/reset fields.
  • ConversationObservation owns context/model/effort.
  • Existing tests become provider-aware.
3

Codex producer and resets

Create TokengochiCodexWriter or TokengochiCodexHook that ingests Codex usage events and writes snapshots.

  • Parse JSONL turn.completed.usage.
  • Roll tokens into a configurable daily/session budget.
  • Capture exact reset count if available; otherwise estimate resets from observed limit-roll events and label the value.
  • Store token totals and reset metadata alongside percent estimates.
4

Two menu-bar creatures

Replace the provider selector with a provider registry that creates one status item and one popover per active provider.

  • Claude creature uses the classic skin by default.
  • Existing PetSkin.claude becomes PetSkin.codex.
  • Codex popover shows reset count near the session/weekly vitals.
  • Freshness text per provider.

Proposed data model

public enum UsageProvider: String, Codable {
    case claude
    case codex
}

public enum UsageSource: String, Codable {
    case claudeStatusline
    case claudePoller
    case codexJsonl
    case codexHook
}

public enum MeasurementKind: String, Codable {
    case exactQuota
    case estimatedBudget
    case estimatedResets
}
public struct UsageSnapshot: Codable {
    var provider: UsageProvider?
    var source: UsageSource?
    var measurementKind: MeasurementKind?
    var sessionPct: Double?
    var weeklyPct: Double?
    var contextPct: Double?
    var inputTokens: Int?
    var outputTokens: Int?
    var reasoningTokens: Int?
    var codexResetsAvailable: Int?
    var codexResetsUsed: Int?
    var codexNextResetAt: Double?
    var updatedAt: Double
}

User-facing copy

Each provider gets its own popover, so the copy can be concrete. Codex can show extra reset state without making Claude carry fields it does not have.

  • Claude no data: "no Claude data yet. start Claude Code or run the poller"
  • Codex no data: "no Codex data yet. start a Codex session"
  • Codex estimated: "estimated from local Codex turns"
  • Codex resets: "3 resets left" or "resets unknown" depending on source quality

Decision

Build multi-provider support first: separate creatures, separate snapshots, separate menu items. Ship Codex as estimated local-activity plus reset metadata if available. Treat exact Codex quota and reset parity as a second track after verifying a live, authorized data source.
